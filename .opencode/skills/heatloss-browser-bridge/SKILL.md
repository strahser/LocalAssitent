# Браузерный мост Qwen (heatloss-browser-bridge)

Передача текста между проектом/конвейером и облачным ИИ Qwen (chat.qwen.ai).
Ты НЕ анализируешь и НЕ принимаешь решений по содержимому ответов — только передача.

## Где скрипты (переиспользуй, не создавай заново)

Все скрипты в `E:\ПлагиныРевит\LocalAssitent\scripts\`:

| Скрипт | Назначение |
|---|---|
| `qwen_send_prompt.py` | Отправка промпта в текущую вкладку chat.qwen.ai (убирает блокирующий оверлей `.page-loading`, вставка nativeSetter, отправка, проверка очистки поля). |
| `qwen_wait_answer.py` | Ожидание стабилизации ответа (2 замера), распознавание «Сетевая ошибка» (код 3 → ретрай), опционально маркер конца. |
| `qwen_read_all_answers.py` | Копирование ВСЕХ ответов через кнопки «Копировать» в один markdown (`pipeline_output\qwen_chat_all_answers.md`). |

## Среда
- LocalAssitent (Selenium, агентские скрипты): `E:\ПлагиныРевит\LocalAssitent\`
- Edge debug-порт: 9222; сессия Qwen с контекстом проекта открыта в браузере.
- Пример конвейера (HeatLossRevit2): протокол `Tasks\00_Протокол_агентов.md`; задания в `Tasks\Конвейер\Браузер\*.txt`.
  Для другого проекта пути/имена задания подставляются свои.

## Формат задания (конвейер HeatLossRevit2)
- Строка 1 — путь сохранения ответа (например `Tasks\00_Референсы\ТЗ_X_Qwen.md`).
- Строки 2–3 — служебные/пустые (не отправляются).
- Строки 4+ — текст промпта для Qwen.
- После взятия задание переносится в `_историю\`.

## Поток работы
1. Прочитай файл задания (строка 1 = путь ответа, строки 4+ = промпт).
2. Отправка: `python scripts\qwen_send_prompt.py --file "<путь к заданию>"`
   - Убирает оверлей `.page-loading` (z=49) → `textarea.message-input-textarea` → nativeSetter
     → отправка кнопкой/Enter → проверка очистки поля.
   - НЕ используй `driver.close()`/`quit()` — это убивает браузер пользователя.
3. Ожидание: `python scripts\qwen_wait_answer.py --timeout 600 --marker КОНЕЦ_ТЗ`
   - Ждёт стабилизации длины; код 3 = «Сетевая ошибка» → ретрай.
4. Чтение полного ответа: `python scripts\qwen_read_all_answers.py`
   (копирование через кнопки «Копировать»; надёжнее DOM-text — innerText может быть обрезан).
5. Сохранение: полный текст ответа в файл из строки 1 + уведомление/коммит по правилам проекта.

## Обработка ошибок Qwen (сам)
Qwen периодически отвечает **«Сетевая ошибка» / «Oops! There was an issue connecting to Qwen...»**
(заглушка сбоя, ответ < ~100 символов). Это НЕ ответ:
1. Переотправь промпт: `python scripts\qwen_send_prompt.py --file "<задание из _истории>"`.
2. Повторилась — подожди 60–90 с и повтори.
3. До 2–3 попыток самостоятельно.
4. После 3 неудач — уведоми контролёра (файлом) и жди указания (смена модели Qwen-Max / повтор).

«Ответ ещё генерируется» (не ошибка): блок растёт/меняется, плашка «Завершено размышление» видна,
кнопок копирования нет. Используй `qwen_wait_answer.py` (2 одинаковых замера или маркер конца).

## Блокирующий оверлей (важно!)
После загрузки страницы над полем ввода может висеть `.page-loading` (z-index 49,
pointer-events: auto) — перехватывает клики и ЛОМАЕТ React-ввод (send disabled, поле не очищается,
хотя value меняется). Решение (вшито в `qwen_send_prompt.py`):
`el.style.pointerEvents='none'; el.style.display='none'` для всех `.page-loading`,
затем вставка nativeSetter + input/change события. Проверено 2026-08-06.

## Правила
- Только передача текста: без пересказа/сокращений/анализа.
- Проверка полноты: маркер конца / длина; обрезанный ответ → сообщи контролёру (browser_partial_*).
- Не трогай чужие задачи, вкладки и отчёты.
